# Ticket 执行入口规则

正常调用只传 ticket；代码解析目录内的票据集、验证定义和依赖图，并为每个直接依赖
选择当前定义下最新的成功验收记录。宿主验收时间决定新旧，宿主顺序号打破同时间并列。
不能使用文件修改时间；最新验收记录或保留的运行报告损坏时失败，不回退旧记录。

代码统一检查工程基线，拒绝未提交工程变更和未跟踪输入，不再豁免整个 specs/。
宿主 session 产物不属于工程输入，但仍受 agent 写保护；绑定的规划文件必须已提交。

代码在 Builder 前保存不可变 work_item 和 delivery-input，绑定 HEAD、依赖引用及配置。
恢复会话沿用选择；新证据出现不改变本次输入。普通交付直接进入 Builder，不启动证据 Scout。
历史验收和 session 内报告保留哈希校验及写保护；引用的源码、测试和业务文档可继续修改，
不因被前置验收引用而锁定。历史通过只证明当时的结果，后续兼容性由当前检查、独立评审
和最终集成验收保障。显式 recheck 保留其证据复核。

Builder 实施，代码运行检查，Reviewer 独立审查，代码控制有上限的修复循环。
文档、提交及最终验收按共享交付链执行；只有宿主可以签发成功验收记录和排序信息。

参数、定义、证据和基线等预检失败用 preflight_rejected 和退出码 2 表达，业务 agent
不启动。允许纠正调用参数后重新预检；不能自动删除、提交或隐藏用户文件，不得修改历史
验收来通过检查。业务运行开始后的终止失败仍停止并报告。

旧记录通过显式 migrate_ticket_history.py 从 schema-v2 宿主完成日志迁移排序信息。
原始验收文件保持不变；日志缺失不能猜测。详细契约见技能 references/tickets.md。
