阶段执行成功 ≠ 整次任务验收成功
测试命令正常跑完时，阶段可以成功，但测试结果仍可能失败。最终还要满足 test.passed and review.approved，再由 run.finish(accepted=...) 统一写入结果。


模板的测试循环上限为 3 轮，审查上限为 2 轮。测试最后一轮失败后仍会调用一次修复，并继续审查；若审查没有触发修改与重测，之前的失败结果不会自动变绿。这里展示代表性路径，折叠了循环和部分日志阶段。

这个文件可以修改吗？


writes: []
不允许留下仓库改动。当前调用的报告与 context_handoff 有狭窄例外。
writes: [路径]
只有匹配的路径可改。修改内容、文件模式、符号链接与 Git index 都会被核验。
省略 / null
可改一般仓库文件，默认受 protected_files 约束；整个 data_dir 并非免检区。

“我完成了”，还需要哪些证明？
每次 Agent 调用都要交回一个 Envelope（结构化 JSON 结果）。运行状态、写入合同、类型校验和业务 gate 共同决定这个结果能否交给下一阶段。

Gate 验证的是可机械检查的声明。
